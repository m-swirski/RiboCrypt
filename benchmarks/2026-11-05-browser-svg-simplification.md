# Large coverage SVG drawing

For SVG line and area coverage traces with more than 5,000 original points, enable Plotly's native screen-space line simplification. Raw x/y arrays, underlying profile, CSV export and hover data are not downsampled. The dynamic browser only enables it when the currently materialized line trace has more than 5,000 points; detailed columns are unchanged. Short traces, stacked plots, animation and guide traces retain their previous behavior. `options(RiboCrypt.browser_simplify = FALSE)` disables the optimization for applications requiring the prior unsimplified SVG paths. This option must be set before app initialization.

In four baseline followed by four optimized headless Chromium software-rendered trials of an existing 109,224-nt human TTN widget on the shared server, the median `Plotly.newPlot` time fell from 1.766 s to 1.367 s for area (22.6%) and from 1.683 s to 1.399 s for lines (16.9%). This does not include the Shiny server, transfer, or all later rendering; trials were not interleaved and machine contention can affect them. Reproduce with `benchmarks/ttn-standalone-widget.cjs` (area) or `benchmarks/ttn-svg-simplify-benchmark.cjs` (lines), using `RENDERER=baseline` and `RENDERER=simplify` on locally generated widgets. The original 109,224 values remain in the traces; smoothing, frame assignments and dynamic k-mer choice are unchanged.

Native SVG simplification approximates the path at display resolution: raster output is not pixel-identical. For the separate 1,400×900 line screenshots, 150,385 of 1,260,000 pixels differed and 20,031 differed by more than 16/255 in at least one channel; mean absolute RGB channel difference was 0.00249. These comparisons cover one view, not a universal visual guarantee. A TTN zoom around its frame-0 maximum produced the same 36,408 source points, peak coordinate (7750), count (19166) and hover text with and without simplification; see `ttn-svg-simplify-hover.cjs`. Unit tests compare complete x/y arrays for frame-split and unframed tracks, with and without templates, at both sides of the threshold; detailed column traces remain unsimplified.

In one unpaired dynamic TTN Shiny test with simplification, Generate-to-initial-view was 6.64 s; programmatic zoom from lines to area took 1.16 s, including 0.49 s for the initial Plotly zoom call; area to columns took 1.48 s. These timings include software rendering and are not directly comparable to earlier trials on a shared server. TTN remains slow in some environments.
A second dynamic TTN run after adding the opt-out measured 5.90 s Generate-to-initial-view, 1.32 s lines-to-area (0.58 s for the first Plotly zoom), and 1.41 s area-to-columns (0.69 s first zoom); these are observations rather than a paired benchmark.
